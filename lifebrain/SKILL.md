# lifebrain — 每日记录 / 项目汇总

数据目录默认 `~/lifebrain/`，以 `config.yaml` 中 `data_dir` 为准。所有结构约定见 `references/format.md`，写入前必须遵守。

## 模式

### 1. 每日记录（默认）
用户说"记一下 / 记录今天"时：

1. 读 `config.yaml` 定位数据目录；读 `journals/` 本周文件（不存在则按 ISO 周命名创建，见 format.md）。
2. 检测空白日期：从本周文件中找出已记录日期，若有漏记的天，**先引导补录**（"你 10-19 没有记录，先补一下昨天做了什么？"），再记今天。
3. 问答式引导，每轮 2-3 个问题，最多 3 轮：
   - "今天主要做了什么？"（按项目追问）
   - 涉及未登记项目 → 提示登记到 `projects.yaml`（名称、类别 work/life、目标），用户确认后写入再继续。
   - "有进展/阻塞值得记吗？"
4. 由回答生成结构化条目行（格式见 format.md），追加到周文件对应日期小节。**用户从不手写格式，从不手写 MD。**
5. 追加后运行 `python3 scripts/rebuild_index.py` 重算项目索引。

### 2. 提醒（reminder 模式）
cron 通过 `scripts/reminder.sh` 无头拉起本 agent。被无头调用且首条消息含 `[lifebrain-reminder]` 时：
- 检查今天是否已有记录：有 → 简短确认即可退出；没有 → 直接进入每日记录问答流程（用户回复会写入）。
- 检测到历史空白日期 → 一并要求补录。

### 3. 周报 / 月报（按需）
用户说"周报 / 月报 / 项目汇总"时：
- 读相关周文件 + `projects.yaml` + 项目索引，聚合生成：
  - 周报/月报：按项目分组的时间投入、关键进展、阻塞；生活类单独一节。
  - 项目汇总：单项目的全部条目时间线 + 阶段总结。
- 生成结果先展示给用户，用户认可后写入 `reports/2026-W43.md` 或 `reports/2026-10.md`，并重跑 `rebuild_index.py`。
- 报告中出现"无记录"的日期要如实标注，不要粉饰。

## 硬性规则
- 周文件是**唯一真相源**：任何数据只写进周文件，项目索引一律由脚本重算，绝不直接编辑 `projects/*.md`。
- 条目行必须是合法结构化行，解析失败的行会在 rebuild 时被丢弃——写完即跑脚本确认无告警。
- 用户回答模糊时追问具体项目名和时长；宁可多问一句，不留脏数据。
